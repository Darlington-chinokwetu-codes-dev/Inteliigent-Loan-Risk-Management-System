# LoanRisk

**Intelligent Loan Risk Assessment System**

LoanRisk is a Flask application that estimates loan default risk from an applicant's income, existing debt, credit history and loan details. It brings the estimate, a risk category and supporting charts into one place, giving a human reviewer a clearer starting point.

The project covers the full workflow: preparing data, comparing machine learning models, saving the selected pipeline and using it through a web interface or JSON API. It was developed as the **Group 17** machine learning project.

**The included data is synthetic.** The app and recorded results demonstrate how the system works; they do not establish how well it would perform on real borrowers. The final lending decision stays with a human reviewer.

## What you can do

- Work through a guided assessment with loan details, applicant information and a review step.
- Load a fictional example to try the app without entering your own details.
- View an estimated default probability, a Low / Medium / High risk category and the loan-to-income ratio.
- Assess primary and secondary applicants separately for education / fees loans.
- Explore grouped loan and income patterns in the bundled dataset.
- Revisit recent assessments, filter them by date or risk, and delete saved history.
- Edit an assessment, print the result and switch between light and dark themes.
- Request predictions from another application using the JSON API.

Review suggestions are generated by rules in the application. They prompt checks such as verifying income or reviewing existing obligations; they are separate from the machine learning model's estimate.

## Run it locally

You will need **Python 3**, **pip** and **Git**.

First, clone the repository and enter the application folder. The Flask app is inside the Group 17 directory, rather than at the repository root.

```bash
git clone https://github.com/Darlington-chinokwetu-codes-dev/Inteliigent-Loan-Risk-Management-System.git
cd Inteliigent-Loan-Risk-Management-System/Intelligent_Loan_Risk_Assessment_Group17
```

On **Windows PowerShell**:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

On **Linux or macOS**:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Open **https://inteliigent-loan-risk-management-sy.vercel.app/** in your browser. A trained pipeline is already included, so you can try an assessment before retraining anything. The launcher starts Flask in development mode for local use.

To get a feel for the workflow, choose a loan purpose, click **Load demo example**, then continue through the applicant and review steps. The example uses fictional details for an education loan and includes both applicants.

Run the commands below from the same application folder, using your virtual environment's Python interpreter. You can activate it with `.\.venv\Scripts\Activate.ps1` on Windows or `source .venv/bin/activate` on Linux/macOS; alternatively, keep using the explicit interpreter paths above.

## Loan purposes and applicant details

| Purpose | API value | Applicant requirement |
| --- | --- | --- |
| Education / fees | `EDUCATION` | Primary and secondary applicants |
| Business venture | `VENTURE` | Primary applicant |
| Personal | `PERSONAL` | Primary applicant |
| Debt consolidation | `DEBTCONSOLIDATION` | Primary applicant |
| Home improvement | `HOMEIMPROVEMENT` | Primary applicant |
| Other | `OTHER` | Web preview only; no risk score |

Education applicants are assessed independently against the same loan amount, interest rate and grade. Their estimates are shown side by side and are not combined into a joint score.

For **Other**, enter a specific description, such as a vehicle loan. The web form displays a confirmation without saving an application or producing a score. The prediction API returns an unsupported-type error for this option. `MEDICAL` is not an accepted prediction purpose in the current app.

The interface uses Indian rupees. Income means **annual income**, while existing debt means the **total outstanding balance**. The loan-to-income ratio is the requested amount divided by annual income; it is not a monthly repayment calculation.

The form accepts ages 18–100 and credit scores 300–850 as input ranges, not as a statement of a lender's eligibility rules. Loan grade is a supplied A–G grade, not a grade calculated by this app.

## How the model works

Training uses an 80/20 stratified train/test split with a fixed random seed. Preprocessing is fitted as part of each model's pipeline:

- Numeric fields use median imputation and standard scaling.
- Categorical fields use the most frequent value for missing entries and one-hot encoding.
- Four classifiers are compared: Logistic Regression, Decision Tree, Random Forest and XGBoost.

The training script selects the model with the highest test-set **ROC-AUC** and saves the complete preprocessing and prediction pipeline with Joblib.

### Recorded demo results

The bundled dataset contains **3,500 synthetic records**. These figures come from the comparison saved in [`outputs/model_metrics.csv`](Intelligent_Loan_Risk_Assessment_Group17/outputs/model_metrics.csv).

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
| --- | ---: | ---: | ---: | ---: | ---: |
| **Logistic Regression** | 80.29% | 62.93% | 73.74% | 67.91% | **0.8676** |
| Random Forest | 81.43% | 66.19% | 70.20% | 68.14% | 0.8571 |
| XGBoost | 81.43% | 70.99% | 58.08% | 63.89% | 0.8517 |
| Decision Tree | 75.14% | 54.48% | 73.74% | 62.66% | 0.7866 |

Logistic Regression is the bundled model because it has the highest recorded ROC-AUC, even though Random Forest and XGBoost have slightly higher accuracy. Treat these as demo results, not evidence of real-world lending performance.

### Reading a result

| Estimated default probability | Risk category |
| --- | --- |
| Below 30% | Low risk |
| 30% to below 60% | Medium risk |
| 60% or above | High risk |

The binary prediction uses a separate 50% threshold: `0` means non-default and `1` means possible default. This is why a medium-risk result can fall on either side of the binary threshold.

## Prediction API

Send a JSON request to **`POST /api/predict`**. With the app running, this Python example makes a personal-loan assessment using only the standard library:

```python
import json
from urllib.request import Request, urlopen

applicant = {
    "person_age": 31,
    "person_income": 750000,
    "person_home_ownership": "RENT",
    "person_emp_length": 5,
    "loan_intent": "PERSONAL",
    "loan_grade": "B",
    "loan_amnt": 220000,
    "loan_int_rate": 10.5,
    "cb_person_default_on_file": "N",
    "cb_person_cred_hist_length": 8,
    "credit_score": 720,
    "existing_debt": 85000,
}

request = Request(
    "http://127.0.0.1:5000/api/predict",
    data=json.dumps(applicant).encode("utf-8"),
    headers={"Content-Type": "application/json"},
    method="POST",
)

with urlopen(request) as response:
    print(json.dumps(json.load(response), indent=2))
```

A successful response includes:

- `default_probability`
- `risk_category`
- `loan_to_income_ratio`
- `predicted_class`
- `predicted_label`
- `message`
- `suggestions`
- `confidence`

Probability is returned as a percentage from 0 to 100; the ratio is returned as a fraction, such as `0.293`.

The `confidence` field is calculated as `max(p, 1 - p) × 100`. It is derived from the model probability, not an independently measured reliability score.

For `EDUCATION`, also supply these eight fields with a `secondary_` prefix:

- `person_age`
- `person_income`
- `person_home_ownership`
- `person_emp_length`
- `cb_person_default_on_file`
- `cb_person_cred_hist_length`
- `credit_score`
- `existing_debt`

For example, the secondary applicant's income is sent as `secondary_person_income`. Their separate estimate is returned under `secondary_applicant`.

Validation errors return **400** with an `error` message. A valid `OTHER` request, including `other_loan_type`, returns **422** because scoring custom purposes is unsupported.

**`GET /health`** provides a simple application health response.

## Retrain the pipeline

The training script reads `data/raw/loan_risk_demo.csv`:

```bash
python -m src.train
```

It compares all four models and updates:

- `models/loan_risk_pipeline.joblib`
- `models/metadata.json`
- `outputs/model_metrics.csv`

To use another dataset, keep the feature names defined in [`src/train.py`](Intelligent_Loan_Risk_Assessment_Group17/src/train.py), including `loan_percent_income`, and provide the binary target `loan_status`:

- `0` = non-default
- `1` = default

Use data with documented permission, provenance and a clear definition of default before drawing conclusions about borrowers.

## History and dataset charts

Applicant inputs are sent to Flask to produce the assessment. The **My history** feature then keeps up to the most recent **100 assessment summaries** in that browser's local storage:

- Assessment time
- Applicant role
- Loan-to-income ratio
- Estimated default probability
- Risk category

It does not store the entered income, debt or credit score in that history. History stays on that browser and can be deleted from the page.

The **Dataset overview** shows grouped outcomes by loan-to-income band. The bundled CSV has no dates, so these charts show patterns across records rather than changes over time.

Distribution-chart groups need at least 10 records, and default rates are hidden for bands with fewer than 20 records. Saved assessment charts show model estimates, rather than observed repayment outcomes.

## Project layout

Application paths below are relative to `Intelligent_Loan_Risk_Assessment_Group17/`.

| Path | Purpose |
| --- | --- |
| `app.py` | Flask routes, request validation and assessment handling |
| `src/train.py` | Preprocessing, model comparison and pipeline saving |
| `src/predict.py` | Feature preparation and prediction |
| `src/risk_utils.py` | Risk categories and review prompts |
| `src/loan_history.py` | Aggregated dataset statistics and chart positioning |
| `src/generate_demo_data.py` | Synthetic dataset generator |
| `data/raw/loan_risk_demo.csv` | Bundled training and demonstration data |
| `models/` | Saved pipeline and metadata |
| `outputs/model_metrics.csv` | Recorded model comparison |
| `templates/` and `static/` | Jinja pages, CSS, JavaScript and browser charts |
| `tests/` | Existing application, prediction and aggregation tests |
| `requirements.txt` | Python dependencies |

The main stack is **Python, Flask, pandas, NumPy, scikit-learn, XGBoost and Joblib**, with **HTML, CSS and vanilla JavaScript** for the interface. No database or user account is needed for the current local demo.

## Where the project goes next

The next useful step is evaluating the workflow on an approved, representative dataset, with an independent test set and checks for probability calibration and fairness.

A shared deployment would also need access controls and a deliberate approach to storing applicant information. The current version remains a local academic prototype.
